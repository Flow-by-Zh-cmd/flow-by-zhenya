# Переезд бота и Mini App «Flow by Zhenya» на бесплатный хостинг

Сейчас бот работает на временном компьютере ассистента через временный туннель (адрес меняется, туннель
иногда падает). Ниже — как перенести его на постоянный бесплатный хостинг.

## Что выбрано

**Основной вариант: Bothost (тариф Starter, 0 ₽) + база данных Neon (Free, 0 $).**

- Bothost — российский хостинг ботов: регистрация по почте, без карты, сайт и мини-приложение открываются
  у пользователей в России, есть HTTPS-адрес и приём вебхуков Telegram.
- На бесплатном тарифе Bothost файлы стираются при перезапуске, поэтому данные (записи, абонементы, заказы)
  хранятся во внешней бесплатной базе Neon (PostgreSQL, 1 ГБ, без карты, без срока).

**Запасной вариант: Render (Free) + Neon.** Условия проверены по официальной документации, но адреса Render
с сентября 2026 не открываются из России без VPN — бот в чате работать будет, а мини-приложение у части
клиентов не откроется. См. раздел «Запасной вариант» в конце.

**Если готовы платить 99 ₽/мес** — тариф Bothost Basic: постоянный диск, переменные окружения, бэкапы,
можно обойтись без Neon. Это самый надёжный вариант для аудитории в России.

### Честные ограничения бесплатного варианта
- Bothost Starter: 1 бот, 256 МБ памяти, 0,5 ГБ диска; на бесплатном тарифе в части описаний указан «спящий режим» —
  первый ответ после простоя может прийти с задержкой.
- По описанию тарифов переменные окружения в панели есть только с Basic. Поэтому всё несекретное лежит в файле
  `config.env`, а строка подключения к базе кладётся туда **в зашифрованном виде** (расшифровать её может только
  программа, знающая токен бота). Токен бота вводится в отдельное поле панели Bothost.
- Neon «засыпает» через 5 минут простоя; первый запрос после сна — на секунду дольше. Лимит 100 CU-часов в месяц
  и 1 ГБ — для студии с запасом.
- Регистрация в Neon из России может показать «Access blocked» — тогда зарегистрируйтесь с включённым VPN
  (работать база потом будет без VPN).
- Состояние незаконченных диалогов (например, оформление заказа) сбрасывается при перезапуске — клиент просто
  начнёт шаг заново. Записи, абонементы, заказы не теряются (они в базе).

## Какие аккаунты нужны (по порядку)
1. **Neon** — база данных.
2. **GitHub** — хранилище кода (Bothost забирает код из репозитория на GitHub).
3. **Bothost** — сам хостинг.

Карта нигде не нужна.

---

## Шаг 1. База данных Neon (≈5 минут)
1. Откройте https://neon.com → **Sign up**. Удобнее всего войти через GitHub или Google (если получите
   «Access blocked» — включите VPN и повторите).
2. Создайте проект: **Create project**
   - Project name: `flow-by-zhenya`
   - Postgres version: оставьте по умолчанию
   - Region: **AWS Europe Central 1 (Frankfurt)** (ближе всего к России)
   - Нажмите **Create project**.
3. На странице проекта нажмите **Connect** (или **Connection string**). Оставьте Branch `main`, Database `neondb`,
   включите **Connection pooling**. Скопируйте строку вида
   `postgresql://neondb_owner:...@ep-...-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require`
4. **Пришлите эту строку ассистенту** (это пароль от базы — больше никому). Ассистент зашифрует её и
   перенесёт туда текущие данные.

## Шаг 2. GitHub (≈5 минут)
1. Зарегистрируйтесь на https://github.com (**Sign up**: почта, пароль, имя пользователя).
2. Справа вверху **+** → **New repository**:
   - Repository name: `flow-by-zhenya`
   - Visibility: **Public** (в коде нет секретов: токена нет, строка базы зашифрована). Если Bothost при подключении
     поддерживает приватные репозитории — можно Private.
   - Нажмите **Create repository**.
3. Загрузка кода — один из двух способов:
   - **Проще всего:** подключите GitHub к ассистенту (он попросит разрешение) — он сам загрузит код.
   - **Вручную:** распакуйте архив `flow-by-zhenya-deploy.zip`, который пришлёт ассистент. В репозитории нажмите
     **uploading an existing file** (или **Add file → Upload files**), перетащите **всё содержимое** папки
     (включая папку `webapp`) → **Commit changes**.

## Шаг 3. Bothost (≈10 минут)
1. Откройте https://bothost.ru → **Регистрация** (почта и пароль), подтвердите почту.
2. В панели нажмите **Создать бота** (или **Добавить бота**) и заполните:
   - **Название:** `Flow by Zhenya`
   - **Платформа:** Telegram
   - **Язык/библиотека:** Python (aiogram)
   - **Bot Token:** токен от @BotFather (рекомендуем перед этим выпустить новый: @BotFather → `/revoke` →
     выбрать бота; новый токен впишите только сюда и пришлите ассистенту)
   - **Git URL репозитория:** `https://github.com/<ваш-логин>/flow-by-zhenya`
   - **Локация:** если есть выбор — зарубежная (Нидерланды); иначе по умолчанию
   - Нажмите **Создать бота**.
3. В настройках бота включите **«Использовать домен»**:
   - выберите бесплатный поддомен (например, `flowbyzhenya` → `https://flowbyzhenya.bothost.ru`, или
     автоматический `*.bothost.tech`);
   - **Порт:** `8080` (программа сама читает порт из переменной `PORT`, которую задаёт Bothost, — главное, чтобы
     порт в панели совпадал).
4. **Пришлите ассистенту адрес домена** (например, `https://flowbyzhenya.bothost.ru`).
   - Если в панели есть раздел **«Переменные окружения»** — можно вписать туда:
     `WEBHOOK_BASE_URL` = адрес домена, `DATABASE_URL` = строка из Neon. Тогда шаг 5 не нужен.
5. Ассистент впишет адрес и зашифрованную строку базы в `config.env` и обновит репозиторий (или пришлёт файл —
   загрузите его в репозиторий с заменой). После этого в Bothost нажмите **Деплой / Перезапустить**.

## Шаг 4. Проверка
1. В логах Bothost должны появиться строки:
   `db: postgres`, `Menu button set to web app https://...`, `Webhook set to https://.../tg/webhook`.
2. Откройте в браузере `https://<ваш-домен>/health` — должно показать `ok`.
3. В Telegram откройте бота, отправьте `/start`, нажмите кнопку меню **«Открыть»** — должно открыться приложение.
4. Владелец: если данные перенесены — права сохранятся; если начинаем с чистой базы — отправьте боту
   `/claim_owner`. Дополнительных владельцев можно добавить в боте: **⚙️ Админ → 👑 Владельцы**.

## Шаг 5. Что сделает ассистент
- Перенесёт данные из старой базы (`migrate_to_postgres.py`) — записи, абонементы, товары, заказы, владельцы.
- **Сразу после запуска на Bothost остановит старую копию бота** на своём компьютере (две копии одного бота
  мешают друг другу: старая отключает вебхук новой).

## Переменные (для справки)
| Переменная | Где | Что это |
|---|---|---|
| `BOT_TOKEN` | поле «Bot Token» в Bothost / env | токен от @BotFather |
| `DATABASE_URL` | env (если есть) | строка подключения Neon |
| `DATABASE_URL_ENC` | `config.env` | та же строка, зашифрованная токеном бота (если env нет) |
| `WEBHOOK_BASE_URL` | env или `config.env` | адрес приложения `https://...`; включает режим вебхука |
| `OWNER_IDS` | env или `config.env` | Telegram ID «постоянных» владельцев через запятую (необязательно) |
| `PAYMENT_PROVIDER_TOKEN` | env | платёжный токен из @BotFather → Payments (когда подключите ЮKassa) |
| `PORT` | задаёт хостинг | порт веб-сервера (по умолчанию 8080) |
| `CANCEL_HOURS`, `TZ_NAME`, `STUDIO_NAME`, `STUDIO_ADDRESS` | `config.env` | настройки студии |
| `TELEGRAM_API_BASE` | env | своё зеркало Bot API, если хостинг не достучится до api.telegram.org |

Если после смены токена бот перестал работать: обновите токен в поле Bothost. Строку базы при этом нужно
перешифровать новым токеном (или задать `DATABASE_URL` в переменных окружения) — ассистент поможет.

## Если что-то не работает
- **502/504 по адресу домена** — порт в панели не совпадает с портом приложения (должно быть одинаково, по умолчанию 8080).
- **В логах `Webhook set`, но бот молчит** — проверьте `https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo`:
  поле `last_error_message`. Убедитесь, что старая копия бота остановлена.
- **`db: sqlite` вместо `db: postgres`** — не подхватилась строка базы (`DATABASE_URL` / `DATABASE_URL_ENC`).
- **Ошибка расшифровки (InvalidToken)** — сменили токен бота; строку нужно перешифровать.

## Запасной вариант: Render + Neon
Подходит, если Bothost не устроит. Минусы: из России без VPN адреса Render не открываются (мини-приложение
у части клиентов не загрузится), сервис засыпает через 15 минут без запросов и просыпается ≈1 минуту
(первый ответ бота после простоя придёт с задержкой). Карта не нужна.

1. Шаги 1–2 (Neon, GitHub) — те же.
2. https://render.com → **Get Started** → войти через **GitHub**.
3. **New → Blueprint** → выбрать репозиторий `flow-by-zhenya` (в нём есть `render.yaml`) → **Apply**.
4. Заполнить переменные: `BOT_TOKEN` (токен), `DATABASE_URL` (строка Neon), `OWNER_IDS` (можно пусто),
   `PAYMENT_PROVIDER_TOKEN` (пусто), `WEBHOOK_BASE_URL` — можно оставить пустым: адрес `https://<имя>.onrender.com`
   подставится автоматически.
5. Дождаться **Live**, проверить `https://<имя>.onrender.com/health` и `/start` в боте.
